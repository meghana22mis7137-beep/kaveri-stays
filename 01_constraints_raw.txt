## Task 1.3: well-formed requests that only conflict with existing data
1. **Duplicate Guest Registration (`POST /guests`)**:
   Payload: `{"full_name": "Aarav Sharma", "email": "AARAV.SHARMA@EXAMPLE.COM", "phone": "+919876543210"}`
   - The JSON syntax and fields are 100% valid.
   - However, the guest table already contains this email (case-insensitive).
   - Database raises `23505` (`uq_guests_email_lower`).
   - HTTP response: `409 Conflict` (`"A guest with this email is already registered"`).

2. **Overlapping Booking Dates (`POST /bookings`)**:
   Payload: `{"guest_id": 5, "room_id": 4, "check_in": "2026-01-12", "check_out": "2026-01-15", "guests_count": 2, "nightly_rate": 3800}`
   - Dates are chronological, occupancy is within limits, foreign keys exist.
   - However, Room 4 already has a confirmed booking for `[2026-01-10, 2026-01-14)`.
   - Database raises `23P01` (`no_overlapping_bookings` exclusion constraint).
   - HTTP response: `409 Conflict` (`"Selected room is already booked for the requested dates"`).

3. **Duplicate Review for Single Booking (`POST /reviews`)**:
   Payload: `{"booking_id": 1, "rating": 5, "comments": "Second review attempt"}`
   - Booking 1 exists and is in `checked_out` status; rating is valid (1-5).
   - However, Booking 1 already has a review in the database.
   - Database raises `23505` (`reviews_booking_id_key`).
   - HTTP response: `409 Conflict` (`"A review has already been submitted for this booking"`).

## Task 1.4: what a client may see from an exclusion violation
When an exclusion constraint violation occurs (SQLSTATE `23P01`), PostgreSQL outputs:
- **Error**: `23P01: conflicting key value violates exclusion constraint "no_overlapping_bookings"`
- **Detail**: `Key (room_id, stay)=(4, [2026-01-12,2026-01-15)) conflicts with existing key (room_id, stay)=(4, [2026-01-10,2026-01-14)).`

A raw database error should never be exposed verbatim to clients. Instead, the FastAPI error handler intercepts SQLSTATE `23P01` and returns:
- **HTTP Status Code**: `409 Conflict`
- **Response Headers**: `Content-Type: application/json`
- **Response Body**:
```json
{
  "status_code": 409,
  "error": "Conflict",
  "code": "ROOM_UNAVAILABLE",
  "message": "The requested room is unavailable for the selected dates because it conflicts with an existing reservation.",
  "constraint": "no_overlapping_bookings"
}
```
If the exclusion violation is from `no_overlapping_rates`, the client instead receives:
```json
{
  "status_code": 409,
  "error": "Conflict",
  "code": "RATE_PLAN_OVERLAP",
  "message": "The specified rate plan validity period overlaps with an existing rate plan for this room type.",
  "constraint": "no_overlapping_rates"
}
```
